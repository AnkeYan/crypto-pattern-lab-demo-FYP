原理

Turbulence Index 由 Kritzman & Li（2010）提出，是量化基金（橋水、Two Sigma 等）實際使用的風險指標。計算公式是：

turbulence(t) = (r_t - μ)ᵀ × Σ⁻¹ × (r_t - μ) # r_t = 當天各資產的回報向量 # μ = 歷史平均回報（rolling 視窗） # Σ⁻¹ = 歷史協方差矩陣的逆矩陣（馬氏距離） # 結果越高 = 市場行為越偏離歷史正常狀態

簡單說：不只看單個資產的波動，而是看「多個資產同時異常」的程度。2008 金融危機、2020 COVID 崩盤的 Turbulence 都極高。

為什麼和你的項目高度匹配
  • 你現有的 F3 GARCH 只看「單幣種波動率是否收縮」，Turbulence 是「市場整體異常程度」，兩者互補不重疊
  • 你已有 BTC + ETH + SOL 每日收盤數據，直接可以計算三幣種的 Turbulence
  • 高 Turbulence 時統計信號失效（你的 Walk-Forward AUC 低），這個因子能讓 Multi-Factor Score 在市場異常時自動降分，更誠實
  • FinRL 已有現成代碼：FeatureEngineer(use_turbulence=True).add_turbulence(df)
具體做什麼
# 新建 scripts/analyze_turbulence.py # 1. 讀 BTCUSDT + ETHUSDT + SOLUSDT 的 close 價格 # 2. 計算 lookback=252 天的 rolling turbulence # 3. 輸出 turbulence_history.csv（date, btc_turb, eth_turb, sol_turb） # analyze_multifactor.py 加入 F12： F12_turb_calm: WEIGHTS["turbulence_calm"] = 0.07 # 低 turbulence → 高分（市場平靜信號更可靠） # 高 turbulence → 低分（市場異常，信號失效風險高）

原理

傳統方法：Markowitz Efficient Frontier（1952）——給定歷史回報和協方差，找出風險調整後最優的資產配比。FinRL 加入了 RL 動態配置，每天根據市場狀態重新調整比例。

# 傳統方法（你可以用 PyPortfolioOpt，已裝好） from pypfopt import EfficientFrontier, risk_models, expected_returns mu = expected_returns.mean_historical_return(price_df) S = risk_models.sample_cov(price_df) ef = EfficientFrontier(mu, S) weights = ef.max_sharpe() # 最大化 Sharpe Ratio 的配比 # 輸出：BTC 42%, ETH 35%, SOL 23% # RL 方法（FinRL env_portfolio_optimization） # Agent 每天觀察市場狀態，動態調整三幣種比例

兩者對比圖就是這個 panel 的核心——用戶能看到「靜態最優配比 vs AI 動態調整」哪個在歷史上表現更好。

為什麼和你的項目高度匹配
  • 你的用戶定位是「持有 BTC/ETH/SOL 的活躍交易者」，「配比怎麼分才對」是他們每天都在想的問題
  • 你已裝好 pyportfolioopt（Backtest step 3 用過），直接可以用
  • 你的數據（2014–今天）非常長，Markowitz 計算結果會很有說服力
  • 沒有任何現有 crypto 工具給「三幣種最優配比」的答案，這是你的差異化

原理

你現有的 Walk-Forward 和 Pattern Validation 是「這個統計信號在新數據上還有效嗎？」，RL Strategy Backtester 問的是：「如果讓 AI 自動根據這些信號買賣，能不能賺錢？」

# RL 交易流程（FinRL CryptoEnv 的邏輯） 每天 Agent 觀察 state: [現金, BTC持倉, ETH持倉, RSI, BB偏差, GARCH波動率, ...] ↓ 輸出 action: [買/賣 BTC 多少, 買/賣 ETH 多少, ...] ↓ Env 執行交易，計算 reward = Δportfolio_value ↓ Agent 從 reward 學習，下次做得更好

最終輸出：RL Agent 策略 vs 買入持有 vs 你現有 Multi-Factor Score 訊號的歷史回報對比圖。

為什麼和你的項目高度匹配
  • 你的 Multi-Factor Score 已有 11 個因子，直接可以作為 RL Agent 的 state 輸入——這是天然的結合點
  • 你已有 XGBoost 預測「7天後漲跌概率」，RL Backtester 是這個方向的自然延伸
  • 用戶問題永遠是「知道有信號，然後呢？」這個 panel 直接回答這個問題

原理

你的 HANDOVER 已寫了「完整量化 Agent 技術棧」。這是把現有的分析層延伸到決策層 + 執行層：

# 你已完成（Step 1 + 2）： 特徵工程（11 因子）→ XGBoost 預測（AUC 0.528） # FinRL 填補（Step 3）： → PPO / SAC Agent（用你的因子作為 state，學習最優執行策略） → 風控層（最大持倉、最大回撤限制） → 執行層（交易所 API，長期目標）

Research tier 後期考慮 開發 2–3 週

匹配度 /100
原理

FinRL 的 Ensemble 策略：同時訓練三個 RL 模型，每隔一段時間用 Sharpe Ratio 選最好的執行。原始論文（NeurIPS 2020）就是用這個框架發表的。

A2C (Advantage Actor-Critic) → 穩定，適合低波動市場 PPO (Proximal Policy Opt.) → 最常用，平衡穩定性和表現 DDPG (Deep Deterministic PG) → 適合高波動，探索性強 # 每 63 天（一季）重新評估，選 Sharpe 最高的模型
為什麼匹配度較低
  • 對你的目標用戶（活躍交易者、newsletter 作者）來說，「哪個 RL 算法更好」太技術性，付費動機弱
  • 開發成本高，需要訓練三個模型，計算時間長
  • ③ RL Strategy Backtester 已能覆蓋用戶核心需求，⑤ 是進階版本
  • 更適合學術展示（你的 FYP 版本）而非商業版本
建議：完成③之後再考慮，或作為 FYP 版本的亮點
